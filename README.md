## Agent hooks (Copilot CLI + Claude Code + OpenCode)
`mkdir -p ~/.config/agent-hooks && cp agent-hooks/*.sh ~/.config/agent-hooks/ && chmod +x ~/.config/agent-hooks/*.sh`

Needs `tmux` and `jq`. On macOS also `brew install flock` for per-window locking (without it the hooks still run, just unserialised). The hooks run on the stock bash 3.2, detach the spinner with perl's `POSIX::setsid` when there is no `setsid` binary, and play `/System/Library/Sounds` through `afplay` when `canberra-gtk-play` is missing.

## Copilot CLI
`cp copilot/settings.json copilot/copilot-instructions.md ~/.copilot/` (install the agent hooks above first)
Hooks (share `agent-hooks/lib.sh`) drive a per-window tmux state machine named after the session: while any parent agent, background agent, or agent-owned shell command works, an animated braille spinner (`spin.sh`, ~8fps, blue) runs on the window. UserPromptSubmit and PreToolUse register the active session ID, including autonomous resumes that have no new user prompt; Stop removes only that session. After the final agent stops, the window enters a `finishing` spinner state until Copilot's own footer reports idle, so a remote build running in another pane does not produce a premature green `✓`. The done marker and completion sound appear only after that idle transition. Per-window locking serializes concurrent lifecycle hooks. When the agent needs input it shows a yellow `(?)`; `AskUserQuestion` (ask_user) and `exit_plan_mode` (plan ready for review) also sound once when entering that state, while permission and elicitation notifications remain silent. The matching PostToolUse hook resumes the spinner once the answer or plan is resolved. The cancellation watchdog clears stale active-agent markers when Copilot returns to its idle prompt without firing Stop. Styles, markers, spinner frames and sounds are centralised in `lib.sh` (`hook_style_*`, `hook_marker_*`, `hook_spinner_frames`, `hook_spinner_delay`, `hook_sound_*`). For debugging, `touch ~/.config/agent-hooks/.debug` to log raw hook payloads to `~/.config/agent-hooks/debug.log` (`rm` the sentinel to stop). The hooks are global across every running Copilot session, so each hook first checks `hook_in_tmux` (`$TMUX`/`$TMUX_PANE`) and no-ops for headless or piped runs: those make no sound and never grab the active pane (`hook_pane` only falls back to `tmux display-message` when `$TMUX` is set).

## Claude Code
`mkdir -p ~/.claude && cp claude/settings.json claude/CLAUDE.md ~/.claude/` (install the agent hooks above first, and fill in the redacted `!Name` path shortcuts in `CLAUDE.md`)
Claude Code shares the same `~/.config/agent-hooks/*.sh` tmux spinner/sound hooks: `claude/settings.json` wires UserPromptSubmit, PreToolUse, PostToolUse, Notification and Stop to them with `HOOK_AGENT=claude`. That switches the footer probe in `lib.sh` to Claude's busy indicator (the live activity line above the input box, e.g. `✶ Creating… (13s · ↓ 892 tokens)`, or `esc to interrupt` on older versions) instead of Copilot's idle footer, adds `ExitPlanMode` as an input tool, and names the window after the conversation title read from the transcript (a `/rename` title wins over the generated one). The spinner re-reads the title every ~5s, since Claude generates it partway through the first turn, and falls back to `claude` until then.

The `settings.json` status line shows the model, effort, context usage with window size (`ctx: 4% of 1M`) and 5-hour/7-day rate limits, with `-` placeholders until the first response arrives.

Pressing `←` on an empty prompt sends the session to the background and opens agent view. To turn that off, switch it off in `/config`, or set the global setting directly: `jq '.leftArrowOpensAgents = false' ~/.claude.json > ~/.claude.json.new && mv ~/.claude.json.new ~/.claude.json` (restart the session afterwards). The setting lives in `~/.claude.json`, which holds machine state and history, so that file is not copied into this repo.

## OpenCode
`mkdir -p ~/.config/opencode/plugins && cp -r opencode/plugins/agent-hooks ~/.config/opencode/plugins/` (install the agent hooks above first)
OpenCode v2 has no shell hooks, so a TUI plugin (`opencode/plugins/agent-hooks/tui.ts`, auto-discovered from `~/.config/opencode/plugins/<name>/tui.ts` and hot-reloaded into running TUIs) drives the same tmux window states through `agent-hooks/opencode.sh <action>` with `HOOK_AGENT=opencode`. It runs inside the TUI process, so `$TMUX_PANE` is the pane showing that TUI, and since the background service broadcasts every session to every TUI it only reacts to root sessions open as tabs in its own TUI. OpenCode reports turn boundaries explicitly, so nothing is scraped from the pane: `session.execution.started` spins, `succeeded` shows the green `✓` (unless a direct subagent is still running), `interrupted` (user, inactivity, shutdown) and `failed` show the red `✗`, a pending `permission.asked` or `form.created` shows the yellow `(?)` until the last one is answered, and `session.renamed` retitles the window. Several tabs running in one TUI share the active-session markers, so the window finishes only when the last one does. Calls run one at a time in event order. The spinner watchdog only checks that `opencode` is still the pane's foreground process and marks the window cancelled if the TUI exits mid-turn. The hooks play no sounds for OpenCode because its built-in `opencode.notifications` plugin already does.

## herdr
`mkdir -p ~/.config/herdr ~/.config/herdr-app && cp herdr/config.toml herdr/sysbar.py ~/.config/herdr/ && cp -r herdr-app/keys.json herdr-app/settings.json herdr-app/mods herdr-app/layouts herdr-app/sounds ~/.config/herdr-app/ && herdr server reload-config` (the tab bar runs `sysbar.py` by absolute path, so adjust `/home/austin` in `config.toml` if your home differs; on macOS keep your own `keys.json` and add the `ctrl-s`, `ctrl-h/j/k/l`, `ctrl-alt-h/j/k/l` and `alt-1` entries to it, since the one here holds the Linux `ctrl-` defaults)
Keybinds mirror `.tmux.conf`: `ctrl+s` prefix, `prefix r` reloads, `prefix %` / `prefix "` split (herdr's `v` / `-` kept too), tmux defaults for `c n p 1-9 x z d , $ & [ ;`, `ctrl+h/j/k/l` focus panes without the prefix, `ctrl+alt+h/j/k/l` swap panes, `prefix h` opens btop in a popup and `alt+1` types the macro text. `herdr/config.toml` covers the terminal `herdr`; `herdr-app/keys.json` maps the same keys for the desktop app as `ctrl-s <key>` sequences. The macro uses `jq` to find the focused pane. Editing `keys.json` stops herdr from adding new default app shortcuts on upgrade, so add those by hand. `prefix x` asks first, like tmux's kill-pane prompt: it opens the `close-pane` mod, a dialog where `y` or Enter closes the pane that was focused and `n` or Esc cancels.

The desktop app plays `herdr-app/sounds/done.mp3` and `request.mp3` through `settings.json` when an agent finishes out of sight or needs input. The `agent-sound` mod (a 1px block in the `my-main` status row) covers the gap by playing the done sound when an agent you are looking at goes from working to idle, and the `my-toast` mod (selected by `"toast"` in the layout) also sends each toast through `notify-send` while the window is unfocused. The sounds are mp3 conversions of the freedesktop `complete` and `message-new-instant` sounds.

The `my-agents`, `my-spaces` and `my-changes` mods are clones of the shipped agents, spaces and changes mods, selected in `layouts/my-main.json`. `my-agents` adds a tree-by-space sort (the default) with a status line per space, urgent agents first, a pin marker, and a Recent section of agents that need you or just finished. `my-spaces` puts the most urgent agent state on each space row. Right-click a space (it opens `my-menu`, a copy of the shipped menu mod with Archive and Resume; copy it to `~/.config/herdr-app/mods/` too) to archive it (or press `a` on the space under the keyboard cursor): it leaves the list for a collapsed Archived section at the bottom (click a row to resume it), the header shows a marker when an agent in an archived space needs you, and the ids live in `~/.config/herdr-app/archived-spaces.json`, which only `my-spaces` writes. Test: `node herdr-app/mods/my-spaces/tests/archive_test.mjs`. `my-changes` is a review panel: syntax highlighted unified or split diffs with wrapped lines and a draggable divider, an Uncommitted or Since main range, per-file reviewed marks, a Tree, List or Risk view (Triage sorts files into Look closely, Normal and Skim with a one-line reason each; rule flags in `mods/my-changes/triage.js` catch removed assertions, skipped tests, silenced errors, new dependencies and sensitive paths without any model), a test status line with a Run tests button, Open in Zed (`o`), and one Ask conversation per space (`claude -p`, with model and effort dropdowns; Tab focuses it) that reads and edits the code, reads the agents' conversation logs and runs the tests through `mods/my-changes/run-tests.sh`, which finds the test command and records each result for the panel. When the focused agent is a child whose review is handed to you (labels `review=yours` and `guide=<json>`), the Since-base view opens a banner with the coordinator's per-file guide (`mods/my-changes/guide.js`): its levels and reasons order the Risk view, and any file that changed after the coordinator's look counts as needing you. Done reviewing marks the child reviewed (it then shows a Reviewed mark), tells its coordinator and takes you back to that coordinator with a toast. Clicking a file opens its diff in a review pane to the right of the focused terminal, one per tab and reused for the next file; ticks show in both the pane and the panel, and with no terminal pane focused the diff stays in the panel. Select diff lines and press `c` (or click the + Comment row) to leave a comment: it goes to the agent that wrote the code, which answers with `hreview reply <id> "<answer>"` (install `.local/bin/hreview` beside `hcoord`; `claude -p` answers when no live agent owns the view), and the thread stays under those lines across reloads, re-anchoring when the diff changes or showing as outdated when the lines are gone. A column on the right of the review pane lists every thread in the folder, grouped by file in diff order, open threads by line and resolved ones dimmed after them, each with its lines, status, first line and reply count under a header such as `4 comments, 1 open`; clicking a row opens its file and scrolls to its card, Comments in the file bar shows or hides the column (remembered), and a narrow pane hides it. Comments and answers draw in Fira Code (one constant, `COMMENT_FONT` in `mods/my-changes/comment_font.js`) and render a safe markdown subset: paragraphs and line breaks, bold, italic, inline and fenced code, bullet and numbered lists with one level of nesting, `#` and `##` headings, quotes, and links shown as their text; anything else stays plain text. Line comments are queued (Ctrl+Enter in the comment bar); Send all (N) in the comment bar under the diff, or Done reviewing, sends them all to the agent as one batch, and the coordinator is told how many went to the child. A coordinator edits no code, so its Changes pane lists its children instead, those waiting for your review first. The `claude-usage` mod, in the sidebar above Settings, shows the current session and weekly limits with their reset times while a reading under 6 hours old exists, and, for sessions that report no limits (Enterprise), an estimated spend for today, the last 7 days and this month (personal sessions are not counted), both at once when both accounts are active; drag the divider above it to resize; `claude/statusline.sh` (the `statusLine` command in `claude/settings.json`, install with `cp claude/statusline.sh ~/.claude/`) saves the limits to `~/.cache/claude/limits.json` (only when reported; `usage.json` is still written) and each session's cost, tagged with whether it had limits, to `~/.cache/claude/cost/` for it. Tests: `bash claude/tests/statusline_test.sh`, `node herdr-app/mods/claude-usage/tests/spend_test.mjs`. `claude/hooks/herdr-session-label.sh`, registered under SessionStart in `claude/settings.json`, labels each agent's herdr terminal with its Claude session id so the Ask can find that log: `cp -r claude/hooks ~/.claude/` and merge the SessionStart entry into `~/.claude/settings.json`.

Both show live system stats. In the terminal `herdr`, `tab_bar_right` runs `herdr/sysbar.py {agents,cpu,mem,net}` every few seconds: agent counts by status, CPU %, used/total RAM and down/up throughput (summed over physical interfaces, skipping `lo`, `veth`, `docker`, `br-`, `virbr`, `tun` and `tap` on Linux and `lo`, `utun`, `gif`, `stf`, `awdl`, `llw`, `bridge`, `ap`, `anpi`, `vmenet` and `vmnet` on macOS). Linux reads `/proc`; macOS has none, so there CPU is the per-process `ps` percentages summed and divided by the core count, RAM is the active, wired and compressor pages from `vm_stat` against `hw.memsize`, and network comes from `netstat -ib`. Rates need a previous sample, kept in `$XDG_RUNTIME_DIR/herdr-sysbar/` (`/tmp` when unset), so they print `--` on the first run. In the desktop app, the `sysbar` mod (`herdr-app/mods/sysbar`) shows the same stats from the same sources every 2s with agent status dots. Herdr replaces its shipped layouts on every start, so the bar lives in two clones: `my-main` (the Herdr layout, with the bar beside `workspace-status` in the bottom row, `chrome: true` matching its background) and `my-terminals` (the Terminals layout, with the bar under the panes). Switch with `ctrl-shift-l`. In `my-main`, the `pane-id` mod (a clone of the `pane` header) shows each terminal's `hc` id (`t3`, `t9`, ...) as a badge, highlighted on the focused pane, and the `status-pane` mod (a clone of `workspace-status`) shows the focused id in the bottom bar. The ids are what `hc read <t>` and `hc send <t> <text>` take, so you can point an agent at a pane by name.

Agents in one herdr space know each other and can message each other. `claude/hooks/herdr-team-context.sh`, registered under SessionStart and UserPromptSubmit in `claude/settings.json`, tells each Claude agent which other agents share its space (name, what it is working on) and how to reach them with Claude Code's own `SendMessage` tool, which works between sessions on one machine and treats a peer's message as information, not an order. A prompt repeats the roster only when someone joined or left. Install with `cp claude/hooks/herdr-team-context.sh ~/.claude/hooks/` and merge the two hook entries into `~/.claude/settings.json`. The hook reads `~/.claude/sessions/*.json` for session names and never touches the `.key` files beside them. The Team panel (`herdr-app/mods/my-team`, a third tab beside Files and Changes) shows one card per agent in the focused space with its status and last action (from the tail of its transcript), each child indented under the coordinator that controls it and a lent child marked, the messages the agents sent each other with a warning when a pair is exchanging a lot, and a collapsible Knowledge section (the space's shared notes and a ledger of its children, with an Open in Zed button). The Team button comes from `mods/my-tabs`, a clone of the shipped `tabs` mod with one more panel button, selected in `layouts/my-main.json`. Copy the mods with `cp -r herdr-app/mods/my-team herdr-app/mods/my-tabs ~/.config/herdr-app/mods/` (without `my-team/tests`) and restart the desktop app. Tests: `bash claude/hooks/tests/herdr-team-context_test.sh` and `node herdr-app/mods/my-team/tests/roster_test.mjs`.

Coordinator mode is on in a space until you switch it off in the Team panel (a checkbox at the top, per space; settings in `~/.config/herdr-team/coordinator.json`). With the mode on, every agent you start in the space is a coordinator (label `role=coordinator`), and agents started by `hcoord spawn` are the spawning coordinator's children. Switching it off clears the role from coordinators only and tells them; children stay children. The panel also has Model (Default, Haiku 5.5, Sonnet 5.5, Opus 5.5, Fable 5.2) and Effort (Default, Low, Medium, High, Extra high, Max) dropdowns for new children (Sonnet 5.5 and Medium until you pick; Default passes no flag so Claude uses its own), which `hcoord spawn` uses unless `--model` or `--effort` is given. `HERDR_COORDINATOR=off` opts a single session out, and leaving Claude on purpose clears its role. A coordinator never edits code: it launches children with `hcoord spawn <name> "<task>"`, each in its own herdr tab and its own git worktree under `.agent-worktrees/` on branch `agent/<name>`, reads their diffs (`hcoord diff`), marks a review under way and records a verdict (`hcoord review <name> reviewing|approved|changes`), hands an approved child to you with `hcoord handoff <name> --summary "..."` (a guide marking which files need your attention, review state `yours`, written to `reviews/<name>.json` in the knowledge dir) and reports briefly. It asks before killing a child (`hcoord kill <name> --worktree`) or merging. A child gets `HERDR_ROLE=child` and treats its coordinator's messages as task instructions; its `coord` label names the coordinator that controls it now, and `owner` is set only while it is lent. Any coordinator can read any child in the space (`hcoord ls --all`, `hcoord diff`, `hc read`), but only the controlling one can review, hand off, kill or lend it; hcoord refuses the others with "belongs to coordinator <t>; ask it over SendMessage". To borrow a child, a coordinator asks its owner over SendMessage, and the owner runs `hcoord lend <name> --to <terminal>`; `hcoord return <name>` (borrower or owner) gives it back. A lent child moves under the borrower in the Agents tree and is told its new coordinator. Child names are unique per space. The judgment lives in `claude/skills/herdr-coordinator/SKILL.md`; what it has learned about you lives in `~/.claude/coordinator/preferences.md` (seed it from `claude/coordinator/preferences.example.md` and copy `claude/coordinator/AGENTS.md` beside it; that folder is private: `AGENTS.md` tells agents never to commit, push or paste it, and `.gitignore` keeps it out of this repo). Each space also has a knowledge dir `~/.claude/coordinator/spaces/<space>/` shared by its coordinators: `notes.md` holds the topic notes (Goal, Workstreams with one line per coordinator, Decisions, Open questions), edited in small edits and never rewritten whole; each coordinator keeps its own plan, children and next step in `coordinators/<session name>.md` (its terminal address when unnamed); and `ledger.jsonl` (written by `hcoord`, including lend and return events; the latest spawn, adopt, lend or return decides who controls a child) and `reviews/` sit beside them. A new or recovering coordinator reads it on start (other agents in the space are pointed at `notes.md`); the start context lists its own surviving children and those whose coordinator is gone, and `hcoord adopt [--from <space-id>]` takes them over, skipping children a live coordinator controls. Install: `cp claude/hooks/herdr-team-*.sh claude/hooks/herdr-session-end.sh claude/hooks/herdr-turn-source.sh ~/.claude/hooks/` and merge the `herdr-turn-source.sh` UserPromptSubmit entry into `~/.claude/settings.json`, `cp -r claude/skills/herdr-coordinator ~/.claude/skills/`, `cp .local/bin/hcoord .local/bin/hcoord-ledger.sh .local/bin/hcoord-adopt.sh .local/bin/hcoord-loan.sh ~/.local/bin/` (hcoord sources the helpers from beside it), then copy `my-team`, `my-agents`, `my-changes` and `my-sound` mods and restart the desktop app. Tests: `bash .local/bin/tests/hcoord_test.sh`, `bash claude/hooks/tests/herdr-team-context_test.sh`, `bash claude/hooks/tests/herdr-session-end_test.sh`, `bash claude/hooks/tests/herdr-turn-source_test.sh`, `node herdr-app/mods/my-sound/tests/alerts_test.mjs`, `node herdr-app/mods/my-agents/tests/parents_test.mjs`, `node herdr-app/mods/my-agents/tests/review_test.mjs`, `node herdr-app/mods/my-team/tests/roster_test.mjs`, `node herdr-app/mods/my-changes/tests/children_test.mjs`, `node herdr-app/mods/my-changes/tests/review_pane_test.mjs`, `node herdr-app/mods/my-changes/tests/comment_anchor_test.mjs`, `node herdr-app/mods/my-changes/tests/comment_threads_test.mjs`, `node herdr-app/mods/my-changes/tests/comment_layout_test.mjs`, `node herdr-app/mods/my-changes/tests/comment_list_test.mjs`, `node herdr-app/mods/my-changes/tests/markdown_parse_test.mjs`, `node herdr-app/mods/my-changes/tests/markdown_rows_test.mjs`, `bash .local/bin/tests/hreview_test.sh`.

Alerts: Herdr's built-in done and blocked sounds cannot skip one agent, so `herdr-app/mods/my-sound` takes them over (it replaces the shipped `agent-sound` in `layouts/my-main.json`) and set `"sounds": {"enabled": false}` in `~/.config/herdr-app/settings.json`. ## AeroSpace
`brew install --cask nikitabobko/tap/aerospace && brew trust --formula felixkratz/formulae/borders && brew install felixkratz/formulae/borders && cp .aerospace.toml ~/`
Keybinds mirror the niri config (`.config/niri/config.kdl`) with niri's `Mod` mapped to `cmd`. Navigation is identical to niri: HJKL focuses, `Ctrl` moves, `Shift` targets monitors, `1`-`9` jump to workspaces, `Ctrl+U`/`I` move a window to the next/previous one, `Q` closes and `M` maximizes. Binds that would shadow core macOS shortcuts (paste, find, close tab, zoom, back/forward, command palette) keep their niri letter but add `ctrl`, e.g. `cmd-ctrl-v` toggles floating, `cmd-ctrl-w` toggles a vertical accordion (niri's tabbed column) whose 60px padding leaves the stacked windows peeking out above and below, `cmd-ctrl-f` fullscreens and `cmd-ctrl-minus`/`equal` resize. `cmd-ctrl-o`/`t` step to the previous/next workspace vim-style, leaving `cmd-u`/`i` for underline/italic. `cmd-ctrl-shift` plus an arrow moves the whole workspace to the monitor in that direction (HJKL with the same modifiers moves only the window). No `alt` binds are used. Other arrow-key variants and niri actions with no AeroSpace equivalent (column presets, centering, overview, workspace reordering) are unbound. Workspaces are dynamic (`config-version = 2` with no `persistent-workspaces`) and the config auto-reloads on save. AeroSpace starts [JankyBorders](https://github.com/FelixKratz/JankyBorders) for a 10px green border on the focused window, with 20px gaps between windows and 16px at the screen edges. `borders` builds from source, so it needs up-to-date Command Line Tools and no outdated Xcode installed. `cmd-shift-m` enters a manage mode for flattening the tree, toggling orientation and joining windows.
