## Copilot CLI
`cp copilot/settings.json copilot/copilot-instructions.md ~/.copilot/` (install the agent hooks above first)
Hooks (share `agent-hooks/lib.sh`) drive a per-window tmux state machine named after the session: while any parent agent, background agent, or agent-owned shell command works, an animated braille spinner (`spin.sh`, ~8fps, blue) runs on the window. UserPromptSubmit and PreToolUse register the active session ID, including autonomous resumes that have no new user prompt; Stop removes only that session. After the final agent stops, the window enters a `finishing` spinner state until Copilot's own footer reports idle, so a remote build running in another pane does not produce a premature green `✓`. The done marker and completion sound appear only after that idle transition. Per-window locking serializes concurrent lifecycle hooks. When the agent needs input it shows a yellow `(?)`; `AskUserQuestion` (ask_user) and `exit_plan_mode` (plan ready for review) also sound once when entering that state, while permission and elicitation notifications remain silent. The matching PostToolUse hook resumes the spinner once the answer or plan is resolved. The cancellation watchdog clears stale active-agent markers when Copilot returns to its idle prompt without firing Stop. Styles, markers, spinner frames and sounds are centralised in `lib.sh` (`hook_style_*`, `hook_marker_*`, `hook_spinner_frames`, `hook_spinner_delay`, `hook_sound_*`). For debugging, `touch ~/.config/agent-hooks/.debug` to log raw hook payloads to `~/.config/agent-hooks/debug.log` (`rm` the sentinel to stop). The hooks are global across every running Copilot session, so each hook first checks `hook_in_tmux` (`$TMUX`/`$TMUX_PANE`) and no-ops for headless or piped runs: those make no sound and never grab the active pane (`hook_pane` only falls back to `tmux display-message` when `$TMUX` is set).

## Claude Code
`mkdir -p ~/.claude && cp claude/settings.json claude/CLAUDE.md ~/.claude/` (install the agent hooks above first, and fill in the redacted `!Name` path shortcuts in `CLAUDE.md`)
Claude Code shares the same `~/.config/agent-hooks/*.sh` tmux spinner/sound hooks: `claude/settings.json` wires UserPromptSubmit, PreToolUse, PostToolUse, Notification and Stop to them with `HOOK_AGENT=claude`. That switches the footer probe in `lib.sh` to Claude's busy indicator (the live activity line above the input box, e.g. `✶ Creating… (13s · ↓ 892 tokens)`, or `esc to interrupt` on older versions) instead of Copilot's idle footer, adds `ExitPlanMode` as an input tool, and names the window after the conversation title read from the transcript (a `/rename` title wins over the generated one). The spinner re-reads the title every ~5s, since Claude generates it partway through the first turn, and falls back to `claude` until then.

The `settings.json` status line shows the model, effort, context usage with window size (`ctx: 4% of 1M`) and 5-hour/7-day rate limits, with `-` placeholders until the first response arrives.

## OpenCode
`mkdir -p ~/.config/opencode/plugins && cp -r opencode/plugins/agent-hooks ~/.config/opencode/plugins/` (install the agent hooks above first)
OpenCode v2 has no shell hooks, so a TUI plugin (`opencode/plugins/agent-hooks/tui.ts`, auto-discovered from `~/.config/opencode/plugins/<name>/tui.ts` and hot-reloaded into running TUIs) drives the same tmux window states through `agent-hooks/opencode.sh <action>` with `HOOK_AGENT=opencode`. It runs inside the TUI process, so `$TMUX_PANE` is the pane showing that TUI, and since the background service broadcasts every session to every TUI it only reacts to root sessions open as tabs in its own TUI. OpenCode reports turn boundaries explicitly, so nothing is scraped from the pane: `session.execution.started` spins, `succeeded` shows the green `✓` (unless a direct subagent is still running), `interrupted` (user, inactivity, shutdown) and `failed` show the red `✗`, a pending `permission.asked` or `form.created` shows the yellow `(?)` until the last one is answered, and `session.renamed` retitles the window. Several tabs running in one TUI share the active-session markers, so the window finishes only when the last one does. Calls run one at a time in event order. The spinner watchdog only checks that `opencode` is still the pane's foreground process and marks the window cancelled if the TUI exits mid-turn. The hooks play no sounds for OpenCode because its built-in `opencode.notifications` plugin already does.

## herdr
`mkdir -p ~/.config/herdr ~/.config/herdr-app && cp herdr/config.toml herdr/sysbar.py ~/.config/herdr/ && cp -r herdr-app/keys.json herdr-app/mods herdr-app/layouts ~/.config/herdr-app/ && herdr server reload-config` (the tab bar runs `sysbar.py` by absolute path, so adjust `/home/austin` in `config.toml` if your home differs)
Keybinds mirror `.tmux.conf`: `ctrl+s` prefix, `prefix r` reloads, `prefix %` / `prefix "` split (herdr's `v` / `-` kept too), tmux defaults for `c n p 1-9 x z d , $ & [ ;`, `ctrl+h/j/k/l` focus panes without the prefix, `ctrl+alt+h/j/k/l` swap panes, `prefix h` opens btop in a popup and `alt+1` types the macro text. `herdr/config.toml` covers the terminal `herdr`; `herdr-app/keys.json` maps the same keys for the desktop app as `ctrl-s <key>` sequences. The macro uses `jq` to find the focused pane. Editing `keys.json` stops herdr from adding new default app shortcuts on upgrade, so add those by hand. `prefix x` asks first, like tmux's kill-pane prompt: it opens the `close-pane` mod, a dialog where `y` or Enter closes the pane that was focused and `n` or Esc cancels.

Both show live system stats. In the terminal `herdr`, `tab_bar_right` runs `herdr/sysbar.py {agents,cpu,mem,net}` every few seconds: agent counts by status, CPU %, used/total RAM and down/up throughput (summed over physical interfaces, skipping `lo`, `veth`, `docker`, `br-`, `virbr`, `tun` and `tap`). CPU and network are rates, so the script keeps the previous sample in `$XDG_RUNTIME_DIR/herdr-sysbar/` and prints `--` on the first run. In the desktop app, the `sysbar` mod (`herdr-app/mods/sysbar`) shows the same stats from `/proc` every 2s with agent status dots. Herdr replaces its shipped layouts on every start, so the bar lives in two clones: `my-main` (the Herdr layout, with the bar beside `workspace-status` in the bottom row, `chrome: true` matching its background) and `my-terminals` (the Terminals layout, with the bar under the panes). Switch with `ctrl-shift-l`. In `my-main`, the `pane-id` mod (a clone of the `pane` header) shows each terminal's `hc` id (`t3`, `t9`, ...) as a badge, highlighted on the focused pane, and the `status-pane` mod (a clone of `workspace-status`) shows the focused id in the bottom bar. The ids are what `hc read <t>` and `hc send <t> <text>` take, so you can point an agent at a pane by name.

## WezTerm
`cp .wezterm.lua ~/`
JetBrainsMono Nerd Font Mono @ 12 (download the Nerd Font above), `Dark+` color scheme (VSCode's default dark theme, bundled with WezTerm), 0.95 background opacity, minimal window (title-bar buttons integrated into the tab bar, which hides itself at a single tab), zeroed top/bottom padding so content fills the height, and system + visual bell. `custom_block_glyphs` is off so braille (e.g. the tmux copilot spinner) renders from the font on the baseline. WezTerm auto-reloads the config on save.

## niri
`mkdir -p ~/.config/niri ~/.local/bin && cp .config/niri/config.kdl ~/.config/niri/ && cp .local/bin/niri-fit-columns ~/.local/bin/` (the binds spawn the script by absolute path, so adjust `/home/austin` in `config.kdl` if your home differs)
`Super+Shift+2/3/4` runs `niri-fit-columns N`, which rebalances the focused workspace's tiled windows into N equal columns that fit the screen.

## AeroSpace
`brew install --cask nikitabobko/tap/aerospace && brew trust --formula felixkratz/formulae/borders && brew install felixkratz/formulae/borders && cp .aerospace.toml ~/`
Keybinds mirror the niri config (`.config/niri/config.kdl`) with niri's `Mod` mapped to `cmd`. Navigation is identical to niri: HJKL focuses, `Ctrl` moves, `Shift` targets monitors, `1`-`9` jump to workspaces, `Ctrl+U`/`I` move a window to the next/previous one, `Q` closes and `M` maximizes. Binds that would shadow core macOS shortcuts (paste, find, close tab, zoom, back/forward, command palette) keep their niri letter but add `ctrl`, e.g. `cmd-ctrl-v` toggles floating, `cmd-ctrl-w` toggles a vertical accordion (niri's tabbed column) whose 60px padding leaves the stacked windows peeking out above and below, `cmd-ctrl-f` fullscreens and `cmd-ctrl-minus`/`equal` resize. `cmd-ctrl-o`/`t` step to the previous/next workspace vim-style, leaving `cmd-u`/`i` for underline/italic. `cmd-ctrl-shift` plus an arrow moves the whole workspace to the monitor in that direction (HJKL with the same modifiers moves only the window). No `alt` binds are used. Other arrow-key variants and niri actions with no AeroSpace equivalent (column presets, centering, overview, workspace reordering) are unbound. Workspaces are dynamic (`config-version = 2` with no `persistent-workspaces`) and the config auto-reloads on save. AeroSpace starts [JankyBorders](https://github.com/FelixKratz/JankyBorders) for a 10px green border on the focused window, with 20px gaps between windows and 16px at the screen edges. `borders` builds from source, so it needs up-to-date Command Line Tools and no outdated Xcode installed. `cmd-shift-m` enters a manage mode for flattening the tree, toggling orientation and joining windows.
